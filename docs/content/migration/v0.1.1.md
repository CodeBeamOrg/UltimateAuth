# Migrating to v0.1.1

UltimateAuth v0.1.1 improves Blazor page authorization by moving `[UAuthAuthorize]` enforcement to the routing layer.

**Most applications require no changes.** If you're using the built-in `UAuthApp` router, authorization works automatically.

Only the following cases require attention.

## 1. Custom Routers

If you use a custom Blazor router, replace `AuthorizeRouteView` with `UAuthAuthorizeRouteView`.

**Before:**

```razor
<AuthorizeRouteView RouteData="routeData" DefaultLayout="typeof(MainLayout)" />
```

**After:**

```razor
<UAuthAuthorizeRouteView RouteData="routeData" DefaultLayout="typeof(MainLayout)" />
```

This enables `[UAuthAuthorize]` enforcement while preserving ASP.NET Core `[Authorize]` support.

Make sure your custom router is rendered inside `UAuthApp`.

## 2. UAuthComponentBase Overrides

`UAuthComponentBase` no longer handles authorization or automatic redirects.

If you previously overrode `OnUnauthorized()` or `OnForbidden()`, replace that behavior with the `NotAuthorized` fragment on `UAuthApp` (built-in router) or `UAuthAuthorizeRouteView` (custom router).

The authentication state change hook is now asynchronous.

**Before:**

```csharp
protected override void HandleAuthStateChanged(UAuthStateChangeReason reason)
{
}
```

**After:**

```csharp
protected override Task HandleAuthStateChangedAsync(UAuthStateChangeReason reason)
{
    return Task.CompletedTask;
}
```

Pages no longer need to inherit from `UAuthComponentBase` to use `[UAuthAuthorize]`.

## 3. Session Requirement

`[UAuthAuthorize]` now defaults to `RequireActive = true`.

If your application intentionally allows authenticated users with a reported inactive session state, explicitly use:

```razor
@attribute [UAuthAuthorize(RequireActive = false)]
```

Otherwise, no change is needed.
